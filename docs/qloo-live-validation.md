# Живая проверка Qloo — 6 октября 2026

## Что подключено

Ключ хранится только в локальном `backend/.env`, исключённом из Git и Docker-контекста; права файла — `600`. Контейнер читает его через read-only подключение файла. Ключ не включён в отчёт, исходники или образ. Поскольку ключ был отправлен в чат, рекомендуется запросить замену и обновить локальную конфигурацию.

Полностью прочитан [Qloo Agentic Hackathon Developer Guide](https://docs.qloo.com/reference/qloo-llm-hackathon-developer-guide). Подключение соответствует руководству: отдельный hackathon-хост, заголовок `X-Api-Key`, GET `/search`, GET `/entities`, GET `/v2/insights`, подтверждённые UUID и `filter.type`. Legacy `/recs` и `/recommendations` не используются. Документация предупреждает, что неподдерживаемые параметры могут игнорироваться, а данные и квоты не гарантируют одинаковое покрытие всех запросов.

## Найденная несовместимость

Поиск и lookup возвращают категории в массиве `types`. Реальный Insights возвращает `type: urn:entity` и `subtype: urn:entity:artist/movie/book`, без массива `types`. Наши исходные синтетические ответы этого не отражали, поэтому первый живой тест остановился с `provider_schema`.

Обработчик теперь принимает обе проверенные формы, сохраняет проверку категории и отклоняет неизвестный subtype, неверный верхнеуровневый type и противоречащие друг другу поля. Добавлены 9 регрессионных проверок на синтетических минимальных данных с наблюдаемой схемой; полные реальные ответы в репозиторий не сохранялись. Описание дополнительно читается из `properties.description`.

## Результаты

- 115 автоматических тестов прошли на SQLite и PostgreSQL 16; два живых теста остаются выключенными по умолчанию.
- Живой поиск David Bowie и рекомендации фильмов на основе найденного UUID прошли.
- Живой агент Qloo + Gemini прошёл; дополнительные проверки подтверждают три категории, допустимые ID, исключение исходных интересов и принадлежность evidence.
- Локальный Docker API работает с обоими ключами; readiness подтверждает подключение к БД.
- Через API создана реальная подборка на основе David Bowie, Radiohead и Björk, сохранена в PostgreSQL и успешно прочитана обратно. Повтор запроса с тем же ключом идемпотентности вернул идентичный снимок.

В одном полном API-прогоне агент выбрал:

## Ограничения и следующий этап

Все три категории вернули результаты, но `exploration_supported` был `false`, а общие теги — пустыми. При недостаточных метаданных приложение честно использует базовый порядок Qloo, а не имитирует различия между Safe и Wild. Следующий этап — проверить получение достаточного профиля тегов и explainability, затем сравнить уровни исследования на реальных данных.

Сам факт валидного плана не доказывает его полезность или неожиданность. Нужны несколько реальных профилей и ручная оценка рекомендаций. Стриминговая доступность, длительность, язык и другие свободные условия ещё не являются проверяемыми фильтрами агента. Интерфейс и публичное размещение пока не реализованы.
